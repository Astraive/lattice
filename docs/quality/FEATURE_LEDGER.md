Do not convert a row to VERIFIED from code, a feature commit, compilation, or an isolated unit test alone.

## Requirements and document reconciliation (initial)

- `docs/README.md`, `docs/REQUIREMENTS.md`, PLAN and TECH_STACK initially scoped Android, Desktop and CLI; Web is now an experimental worker-backed browser profile with same-origin two-profile messaging, while iOS remains excluded. WEB-001–009 remain traceable requirements; Web is not a supported or release-ready client.
- Feature catalog owners now include Web (WEB) alongside identity (IDN), spaces (SPC), messaging (MSG), networking (NET), files (FIL), voice (VOC), mobile (MOB), desktop (DSK), and CLI. Cross-cutting LAT requirements add offline/no-account behavior, event identity across re-enveloping, authorization-before-projection, truthful delivery states, non-authoritative carriers, bounded resource use, deterministic projection, secure storage, privacy, version negotiation, accessibility, optional infrastructure, migrations and measured claims.
- Protocol documents/spec files call themselves candidates/drafts and prohibit an interoperability claim. ADR-001/002 are accepted policy decisions but still require behavioral evidence; ADR-003 is a candidate profile without two-relay proof; ADR-004/005/006/007 are open/deferred scope, not hidden implementation requirements to silently change.
- Current accepted implementation is mostly a set of bounded Rust component candidates; local Space genesis, offline authored queue and some local queries exist. Real CLI↔CLI authenticated reconciliation and the HTTP-loopback Web↔CLI path now pass recorded process/browser acceptance; Desktop/Android communication and production Web support remain unverified or unsupported. `docs/features/mobile.md` explicitly says GATT does not advertise/authenticate/exchange; Desktop docs constrain message sync/transfer claims; CLI docs state local send and Welcome artifacts do not imply delivery/membership; voice docs identify missing native SDKs.
- `docs/TODO.md` is not sufficient as an inventory; it omits historical feature commits and some newly required cross-client behavior. This ledger is additive traceability and does not mark old TODOs complete.

## Initial current-source mapping observations

These are read-only source-path findings, not runtime acceptance evidence. All related capabilities remain `PENDING-AUDIT` until their specified behavior is exercised.

- **Protocol bindings (initial finding resolved for the candidate inspector):** `EventKind::Ephemeral = 10` and non-contributory X25519 identity keys now have matching Rust/TypeScript validation, with a shared candidate signed-event vector. Inspector byte, string, collection, and nesting bounds now match `02-encoding.md`. Tests establish vector behavior, not client transport interoperability.
- **Core and MLS:** Core has real signed/encrypted local event storage, outbox and authorization/projection boundaries. Message-history reducer state is in-memory; local durable text cache is narrower than the reducer. MLS production credential admission requires OS-rooted X.509 chain, matching Ed25519 SPKI and canonical identity SAN. MLS conflict markers retain exact signed controls, persist with received events, and are revalidated on local restore; invited-device restoration requires its Welcome checkpoint. Welcome bootstrap is a local pinned-inviter checkpoint, not live invite delivery. Invite token policy validation has no production callsite.
- **Sync and carriers:** CLI and the Desktop `sync_local_space_once` command bind bounded authenticated v2 sync to Core acceptance; only CLI↔CLI has a real process reconciliation run. Desktop provides one explicit bounded round, not full convergence; repeat sessions are required where history remains incomplete. TCP is a byte carrier. Router planning has no production caller. Courier queue/TCP primitives have manual CLI/Desktop callsites; relay publish/retrieve APIs have no product callsite and no received-event-to-Core path.
- **Android:** Compose reaches local UniFFI/Core operations and the scanner; GATT central/peripheral adapters are not instantiated, there is no advertiser, and no GATT-to-Core bridge or Core projection observer is wired. The persistent nearby service reports scan status only.
- **Voice:** `lattice-voice` exposes a local signaling state machine and explicitly returns `MediaStatus::NotImplemented`; no production consumer or Android/Desktop media backend is present in the audited paths.
- **Scaffolds:** `tests/{e2e,interop,mesh,mobile,protocol,routing,security,sync}`, `tooling/{benchmarks,fuzz,mesh-simulator,network-chaos,packet-inspector}`, `design/{assets,icons,scripts,tokens}`, `protocol/schemas`, and root `transports` are placeholder-only. `fuzz/fuzz_targets` contains six Rust targets: canonical, signed event, identity bundle, attachment manifest, Nostr event and relay envelope. `protocol/specs` and `protocol/vectors` contain actual files plus stale `.gitkeep`.
- **PKI tooling:** the example now uses accepted `space create --credential ... --channel general` flags. On Windows, the development CA/leaf/vector scripts were exercised with PowerShell 7.6.6 and OpenSSL 3.6.0 against the production CLI validator using Current User Root trust; positive local Genesis and wrong-key, expired, and untrusted-root rejection passed. Android/Desktop trust bootstrap remains unverified.

- **SQLite transactions and outbox (source audit):** schema migrations 1–13 apply each DDL change and `user_version` update in one `IMMEDIATE` transaction; open configures WAL, foreign keys, and a busy timeout, and rejects newer schemas. Event bytes, parent links, pending-row deletion and optional outbox insert are transactional; Core's SQLite-backed OpenMLS provider shares the authored-event transaction. Persisted outbox bounds are currently applied to every row and all envelope bytes, including terminal `delivered`/`failed` records; those states are never pruned. Therefore the nominal queue limits can become a lifetime send limit after 1,024 retained envelopes or 16 MiB, even after delivery/failure. The architecture specifies outbox retention only until acknowledgment/expiry/retry end, so terminal-state cleanup/status retention needs a deliberate lifecycle contract before changing behavior. Migration crash atomicity follows SQLite transaction structure; process-kill crash recovery was not exercised.
- **Authenticated synchronization (source audit):** the deterministic planner rejects cross-summary sequence forks, bounds author/event/gap/request/dependency sets, requests exact pending dependency IDs before sequence ranges, and reports explicit retention gaps rather than claiming completeness. Direct v2 sync binds Noise to the pinned identity, scopes both summary and event source to one selected Space generation, validates event signatures/metadata on source and response, then hands bytes back to Core for MLS/policy admission; CLI reconciliation persists accepted events, retries pending dependencies, and repeats fresh summaries in bounded rounds. The Store summary source verifies stored records and fails on its budget, but it scans/verifies the profile-wide event table before filtering the selected generation; >16,384 profile events or >16 MiB scanned bytes can prevent syncing a small scope. Existing test coverage exercises planner cases and one authenticated TCP range-repair exchange; it does not exercise cross-process CLI reconciliation, out-of-order parent/child repair through the full CLI/Core path, or multi-round convergence/restart.
- **Routing, path negotiation, and health (source audit):** route planning applies caller-supplied reachability, capability, internet/metered, energy, loss, queue, RTT, MTU/frame, expiry, hop/copy/fanout and traffic-class policy, with deterministic class-specific ranking. Authenticated path-upgrade offers exchange a versioned canonical-CBOR intersection only after pinned Noise identity proof and caller authorization; comments correctly state this does not discover or open a path. `PathHealthTracker` records bounded local lifecycle, exact-hop send outcomes and successful receives without inferring recipient delivery. No production caller was found for `plan_forward`, `PathHealthTracker`, or authenticated capability negotiation; Android only probes and displays local Wi-Fi availability. Thus route fallback, failure-driven path switching, or operational health-based planning are not wired into an app.
- **Courier queue and forwarding (source audit):** persistence is disabled by default; explicit configuration is bounded by hard object/peer/total byte and item ceilings, expiry, event/envelope deduplication, FIFO quota eviction, and transactional budget consumption. One transfer authenticates an exact pinned peer over Noise, validates the signed envelope/expiry/budgets, moves it in bounded 60,000-byte chunks, and acknowledges only after local receiver queue retention. CLI and Desktop expose manual pinned TCP listener/forward operations. Forwarding decrements hop/copy budget and deletes the source row after peer authentication but before the first transfer frame; a later disconnect or remote queue rejection permanently loses that queued copy. This is documented policy, not failure-preserving retry. Tests establish queue quotas/reopen and one-hop TCP transfer/pin mismatch; no three-node forwarding, post-consumption disconnect, or automatic carry/retry was exercised.
- **Optional relay transport (source audit):** the candidate profile separates the Nostr relay signing key and private mailbox token from the Lattice device identity; outer kind/tag/expiry, canonical envelope ID, inner signed event, and expiry are checked together. NIP-01 verification rejects invalid IDs/signatures/duplicate or unknown fields; NIP-11 has bounded duplicate-key-rejecting parsing and publishing requires NIP-40 plus a sufficient advertised frame size. HTTPS redirects are disabled; operations require `wss://`, finite timeout/frame/aggregate/event bounds, exact positive `OK` for publish, exact mailbox retrieval, and cancellation/close handling. Relay acceptance is recorded as `Forwarded`, not `Delivered`. CLI currently probes NIP-11 only; no application caller for outbox publication or retrieval was found, and `network.rs` tests cover URL/filter/frame parsers rather than a live or mock HTTP/WebSocket exchange. No independent relay pair or end-client receipt path was exercised.
- **Attachments, transfer authorization, resume, and cleanup (source audit):** manifest events are policy-authorized and atomically queued as metadata/digests; bytes stay in local staging. Direct transfer uses a pinned Noise session, event-bound transfer ID, caller authorization, explicit receiver consent, bounded chunk frames, per-chunk and whole-file SHA-256 verification, and final ACK only after full verification. The Desktop UI is wired to select/cache, manually send/receive, consent, and export via non-overwriting temporary files; source and staging quotas are bounded, received chunks are resumable after reopen, and expired/orphan staging is cleaned. Desktop caps files at 128 MiB with 512 MiB/64-transfer staging quotas and seven-day retention; Android and CLI have no transfer UI. `cargo test -p lattice-files` passed 16 tests; `cargo test -p lattice-node attachment_transfer` passed 3 scenarios (authenticated transfer/resume, consent rejection, silent-peer timeout). Evidence does not cover a process-kill transfer resume end-to-end, Desktop UI runtime, or Android transfer.
- **Search, ephemeral presence/typing, and local mention mutes (source audit):** offline search decrypts only the bounded local per-channel cache, normalizes with Unicode lowercase substring matching, returns at most 100 newest matches, and re-verifies signatures/metadata for each returned event; Desktop and CLI invoke it, while Android has generated UniFFI but no product callsite was found. Remote authorized edits replace cached content. Remote authorized tombstones previously left the encrypted text cache row searchable; Core now deletes the scoped cache row transactionally with accepted tombstones, and the received edit/tombstone scenario asserts both search and local history exclude it. Presence/typing payloads are canonical and bounded (60-second presence, 10-second typing), keyed per Space generation/member/kind, active-member/conflict checked, replay-sequenced and monotonic-time expired in an in-memory table; tests cover duplicate/stale sequence and expiry, but no production sender, receiver, or observer uses the table. Mention mutes are encrypted device-local identity/role target preferences (4,096 bound) and survive Core profile reopen; notification eligibility takes already-resolved local targets, but no app binding or notification consumer was found.
- **Security negatives before projection (source audit):** `accept_synced_application_event` verifies the signed event, checks exact selected generation and dependencies, processes/binds the MLS application, runs policy authorization, and only then persists the event and local text projection in one SQLite/OpenMLS transaction; non-authorized results become errors before projection, with the transaction uncommitted. Existing tests reject MLS author/ciphertext/epoch/group/fingerprint mismatches before releasing plaintext; reducer tests reject nonmembers, denied channel permissions, incomplete heads, invalid targets, and authorization before event storage. One direct storage-path negative asserts denied signed/MLS-bound input has no event row. No end-to-end transport-delivered invalid sender/group/permission test currently asserts both durable history and search remain empty; system-level security acceptance is still pending.
- **Bounded fuzz campaigns (Windows):** added a structured `sync-plan` libFuzzer target exercising per-author sequences, same-sequence event-ID disagreements, gaps, and dependency inputs; documented it in the test plan and registered the `lattice-sync` dependency. With nightly Rust, default AddressSanitizer, the installed MSVC `clang_rt.asan_dynamic-x86_64.dll` on `PATH`, `ASAN_OPTIONS=quarantine_size_mb=64:thread_local_quarantine_size_kb=256`, and `-max_len=4096`, bounded campaigns completed without crash: canonical 661 executions, signed-event 641, identity-bundle 127,458, sync-plan 32,807, relay-envelope 1,109,096, and nostr-event 1,265. These are short smoke budgets, not release-strength coverage; Windows MSVC cannot run this harness with `--sanitizer none` because the coverage-section linker symbols remain unresolved.
- **BLE profile/migration boundary:** `protocol/specs/10-ble.md` assigns `pre-profile`, `lattice-ble-exp0`, and reserved `lattice-ble-v1` labels; exp0 is metadata, not an on-air string or interoperability claim. Candidate exp0 UUIDs cover one service and five characteristics; its 31-byte legacy advertisement carries discriminator `0` and a fresh 72-bit random token rotated every 900 monotonic seconds, with sightings memory-only and capped at 1,024. The candidate handshake uses Noise XX plus post-Noise Ed25519 proofs binding both exact identity bundles, observed discovery token and session transcript; first contact requires matching a 48-bit session string and explicit full-fingerprint pin. Android still scans the old pre-profile UUID, deduplicates session-salted device-address digests rather than tokens, and has no advertiser or authenticated GATT message path. ADR-005 and the candidate fixture now define the exp0 design, but negative/replay coverage, platform wiring, passive-capture review, and physical acceptance remain open.
- **BLE framing and retry contract:** ADR-005 records the exp0 candidate values: 154-byte ATT-MTU floor, 24-byte header, 110-KiB envelope cap, 1,024-fragment ceiling, four-fragment credit window, 30-second assembly lifetime, and Router-owned retry. The fixture covers advertisement/prologue, deterministic identity records, control records, and frame boundaries; malformed/replay coverage, a reproducible Noise ciphertext vector, Android implementation, and device acceptance remain release gates. No interoperability evidence is claimed.

Source-only audit lanes are being consolidated against exact production callsites, tests and requirement provenance; none of these observations imply an end-to-end pass.
