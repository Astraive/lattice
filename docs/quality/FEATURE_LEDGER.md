## Initial current-source mapping observations

These are read-only source-path findings, not runtime acceptance evidence. Current capability classifications are in the table below; source mapping alone cannot move a capability to `VERIFIED`.

- **Protocol bindings (initial finding resolved for the candidate inspector):** `EventKind::Ephemeral = 10` and non-contributory X25519 identity keys now have matching Rust/TypeScript validation, with a shared candidate signed-event vector. Inspector byte, string, collection, and nesting bounds now match `02-encoding.md`. Tests establish vector behavior, not client transport interoperability.
- **Core and MLS:** Core has real signed/encrypted local event storage, outbox and authorization/projection boundaries. Message-history reducer state is in-memory; local durable text cache is narrower than the reducer. MLS production credential admission requires OS-rooted X.509 chain, matching Ed25519 SPKI and canonical identity SAN. MLS conflict markers retain exact signed controls, persist with received events, and are revalidated on local restore; invited-device restoration requires its Welcome checkpoint. Welcome bootstrap is a local pinned-inviter checkpoint, not live invite delivery. Invite token policy validation has no production callsite.
- **Sync and carriers:** CLI and the Desktop `sync_local_space_once` command bind bounded authenticated v2 sync to Core acceptance; only CLI↔CLI has a real process reconciliation run. Desktop provides one explicit bounded round, not full convergence; repeat sessions are required where history remains incomplete. TCP is a byte carrier. Router planning has no production caller. Courier queue/TCP primitives have manual CLI/Desktop callsites; relay publish/retrieve APIs have no product callsite and no received-event-to-Core path.
- **Android (initial audit finding updated):** the initial source audit found no advertiser or GATT-to-Core application bridge; current branch now routes bounded exp0 authenticated BLE packets into Core and has an authenticated pinned TCP DM path in UniFFI. Compose still exposes local BLE/TCP operations rather than a complete auto-discovery workflow, the persistent nearby service reports scan status only, and physical device behavior remains unverified; see the current-branch DM refresh row.
- **Voice:** `lattice-voice` exposes a local signaling state machine and explicitly returns `MediaStatus::NotImplemented`; no production consumer or Android/Desktop media backend is present in the audited paths.
- **Scaffolds:** `tests/{e2e,interop,mesh,mobile,protocol,routing,security,sync}`, `tooling/{benchmarks,mesh-simulator,network-chaos,packet-inspector}`, `design/{assets,icons,scripts,tokens}`, `protocol/schemas`, and root `transports` are placeholder-only. `fuzz/fuzz_targets` contains nine Rust targets: canonical, signed event, identity bundle, attachment manifest, Nostr event, relay envelope, sync plan, NIP-11, and path upgrade. `protocol/specs` and `protocol/vectors` contain actual files plus stale `.gitkeep`.

On Windows, the development CA/leaf/vector scripts were exercised with PowerShell 7.6.6 and OpenSSL 3.6.0 against the production CLI validator using Current User Root trust; positive local Genesis and wrong-key, expired, and untrusted-root rejection passed. Android/Desktop trust bootstrap remains unverified.

- **SQLite transactions and outbox (source audit):** schema migrations 1–13 apply each DDL change and `user_version` update in one `IMMEDIATE` transaction; open configures WAL, foreign keys, and a busy timeout, and rejects newer schemas. Event bytes, parent links, pending-row deletion and optional outbox insert are transactional; Core's SQLite-backed OpenMLS provider shares the authored-event transaction. Persisted outbox bounds are currently applied to every row and all envelope bytes, including terminal `delivered`/`failed` records; those states are never pruned. Therefore the nominal queue limits can become a lifetime send limit after 1,024 retained envelopes or 16 MiB, even after delivery/failure. The architecture specifies outbox retention only until acknowledgment/expiry/retry end, so terminal-state cleanup/status retention needs a deliberate lifecycle contract before changing behavior. Migration crash atomicity follows SQLite transaction structure; process-kill crash recovery was not exercised.
- **Authenticated synchronization (source audit):** the deterministic planner rejects cross-summary sequence forks, bounds author/event/gap/request/dependency sets, requests exact pending dependency IDs before sequence ranges, and reports explicit retention gaps rather than claiming completeness. Direct v2 sync binds Noise to the pinned identity, scopes both summary and event source to one selected Space generation, validates event signatures/metadata on source and response, then hands bytes back to Core for MLS/policy admission; CLI reconciliation persists accepted events, retries pending dependencies, and repeats fresh summaries in bounded rounds. The Store summary source verifies stored records and fails on its budget, but it scans/verifies the profile-wide event table before filtering the selected generation; >16,384 profile events or >16 MiB scanned bytes can prevent syncing a small scope. Existing test coverage exercises planner cases and one authenticated TCP range-repair exchange; it does not exercise cross-process CLI reconciliation, out-of-order parent/child repair through the full CLI/Core path, or multi-round convergence/restart.
- **Routing, path negotiation, and health (source audit):** route planning applies caller-supplied reachability, capability, internet/metered, energy, loss, queue, RTT, MTU/frame, expiry, hop/copy/fanout and traffic-class policy, with deterministic class-specific ranking. Authenticated path-upgrade offers exchange a versioned canonical-CBOR intersection only after pinned Noise identity proof and caller authorization; comments correctly state this does not discover or open a path. `PathHealthTracker` records bounded local lifecycle, exact-hop send outcomes and successful receives without inferring recipient delivery. No production caller was found for `plan_forward`, `PathHealthTracker`, or authenticated capability negotiation; Android only probes and displays local Wi-Fi availability. Thus route fallback, failure-driven path switching, or operational health-based planning are not wired into an app.
| **Courier queue and forwarding (source audit):** persistence is disabled by default; explicit configuration is bounded by hard object/peer/total byte and item ceilings, expiry, event/envelope deduplication, FIFO quota eviction, and transactional budget consumption. One transfer authenticates an exact pinned peer over Noise, validates the signed envelope/expiry/budgets, moves it in bounded 60,000-byte chunks, and acknowledges only after local receiver queue retention. CLI and Desktop expose manual pinned TCP listener/forward operations. The initial audit found that forwarding deleted the source row before transfer; the current-branch fix retains it until an authenticated ACK carrying the exact forwarded envelope ID. Successful transfer, missing-ACK retention after receiver storage, and pin-mismatch preservation are tested. Courier acceptance is hop retention, not destination delivery. |
- **Optional relay transport (source audit):** the candidate profile separates the Nostr relay signing key and private mailbox token from the Lattice device identity; outer kind/tag/expiry, canonical envelope ID, inner signed event, and expiry are checked together. NIP-01 verification rejects invalid IDs/signatures/duplicate or unknown fields; NIP-11 has bounded duplicate-key-rejecting parsing and publishing requires NIP-40 plus a sufficient advertised frame size. HTTPS redirects are disabled; operations require `wss://`, finite timeout/frame/aggregate/event bounds, exact positive `OK` for publish, exact mailbox retrieval, and cancellation/close handling. Relay acceptance is recorded as `Forwarded`, not `Delivered`. CLI currently probes NIP-11 only; no application caller for outbox publication or retrieval was found, and `network.rs` tests cover URL/filter/frame parsers rather than a live or mock HTTP/WebSocket exchange. No independent relay pair or end-client receipt path was exercised.
- **Attachments, transfer authorization, resume, and cleanup (source audit):** manifest events are policy-authorized and atomically queued as metadata/digests; bytes stay in local staging. Direct transfer uses a pinned Noise session, event-bound transfer ID, caller authorization, explicit receiver consent, bounded chunk frames, per-chunk and whole-file SHA-256 verification, and final ACK only after full verification. The Desktop UI is wired to select/cache, manually send/receive, consent, and export via non-overwriting temporary files; source and staging quotas are bounded, received chunks are resumable after reopen, and expired/orphan staging is cleaned. Desktop caps files at 128 MiB with 512 MiB/64-transfer staging quotas and seven-day retention; Android and CLI have no transfer UI. `cargo test -p lattice-files` passed 16 tests; `cargo test -p lattice-node attachment_transfer` passed 3 scenarios (authenticated transfer/resume, consent rejection, silent-peer timeout). - **Search, ephemeral presence/typing, and local mention mutes (source audit):** offline search decrypts only the bounded local per-channel cache, normalizes with Unicode lowercase substring matching, returns at most 100 newest matches, and re-verifies signatures/metadata for each returned event; Desktop and CLI invoke it, while Android has generated UniFFI but no product callsite was found.
