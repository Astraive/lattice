# Transport behavior matrix

A transport is an opaque carrier; it does not establish message delivery, authorization, or authoritative state. Rows separate component evidence from a live product path.

| Transport/path | Implemented surface | Runtime evidence | Status / limitation |
| --- | --- | --- | --- |
| Authenticated CLI direct TCP sync | CLI/Node v2 session and Core acceptance | Two-process CLI reconciliation passed; quality-ledger run log | VERIFIED for recorded CLI path. |
| Desktop direct sync / peer courier | Bounded authenticated v2 sync command with Core event acceptance; persistent courier remains a separate opaque-envelope path | Independent Tauri Desktop profiles in the same Space exchanged authorized history after restart. Receiver sync reported `accepted 1, pending 0, duplicates 0, checkpoint-excluded 1`; the fresh event projected, the older checkpoint-covered ciphertext did not, and sender history contained the reverse-direction event. Exact run and event IDs are in [`INTEROP_MATRIX.md`](INTEROP_MATRIX.md). | VERIFIED for the recorded checkpoint-aware Desktop↔Desktop path and the one-round Desktop↔CLI event path; full convergence, removal/rekey, courier delivery and Android/Web interop remain unverified. |
| Android BLE | Experimental exp0 advertiser/scanner, GATT central/peripheral, authenticated session and Core packet routing; central requires exact capabilities before session traffic | Candidate JSON vectors are consumed by Rust identity/Noise tests and Android JVM conformance tests; no physical offline Android pair test is available and the workstation lacks devices/adb | BLOCKED-EXTERNAL for physical acceptance; JVM/source coverage is not device or interoperability evidence. |
