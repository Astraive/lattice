# Web client — WEB

**Status:** Experimental browser implementation; not supported for production or full release. The local profile, offline enrollment/invitation, same-origin two-profile messaging, manually signaled WebRTC, and one-session CLI loopback exchange are implemented and exercised in managed Chromium. Browser compatibility, WAN/networking, accessibility, security review, quota/crash matrix, and release compatibility remain open. Architecture details are in [architecture.md](../architecture.md).

## Delivery boundary and remaining gates

The TypeScript UI delegates Core operations to a dedicated Rust/WASM worker. The worker uses SQLite in OPFS and serializes profile operations; the OPFS directory is derived per profile so distinct profiles can be open concurrently. A same-origin lock still prevents a second tab from opening the same profile. Unsupported secure contexts or browser storage fail closed; there is no volatile fallback.

The browser build and runtime smoke exercise pinned issuer enrollment, CA-issued Ed25519 identity certificates, Core-created Space genesis, KeyPackage/Welcome membership, explicit inviter fingerprint pinning, signed MLS message exchange, and persisted message history after full page reload. Two independent profiles in managed Chromium exchanged messages over same-origin `BroadcastChannel`; each receiving worker passed canonical signed event bytes through Core signature, group, MLS and projection validation.

The WebRTC event link uses an ordered binary `RTCDataChannel` to carry canonical signed event bytes from the bounded Core outbox. Offer/answer SDP is transferred manually out of band; there is no signaling service or default STUN/TURN service. Users may explicitly supply at most eight ICE servers as JSON; only `stun:`, `stuns:`, and credentialed `turns:` URLs are accepted. ICE credentials remain in page memory and are cleared when the profile is locked. SDP can expose network candidates; use a trusted transfer channel. The carrier does not authorize group membership: every received frame goes through the receiving profile's Core signature, generation, MLS and authorization checks.

The WebRTC reconciliation pages the selected Space outbox from its first page on data-channel open and after successful ICE restart. Each frame is at most 256 KiB or the negotiated lower data-channel maximum, aggregate reconciliation is capped at 16 MiB, and data-channel backpressure is bounded. Core event IDs make replayed pages idempotent; transport acceptance does not produce recipient-delivery receipts. Managed Chromium smoke used two independent OPFS profiles, replaced `BroadcastChannel` with a no-op, established the WebRTC channel using manual SDP transfer, observed Core validation of inbound event frames, restarted ICE, and observed one 476-byte event reconciled through the peer link. This verifies a browser-local loopback path, not NAT traversal or WAN reachability.

Invitation remains an offline manual transfer: users move the KeyPackage, Welcome bootstrap, public identity bundle, and independently verify the inviter's full fingerprint out of band. `BroadcastChannel` remains an untrusted same-origin carrier for open tabs. WebRTC's data channel is browser-to-browser. The CLI also exposes `sync web-serve-once`, a one-session `ws://` loopback bridge paired by a one-time token and exact HTTP Origin; managed Chromium exchanged Core-accepted MLS events in both directions with the native CLI. The socket is intentionally HTTP-loopback only: HTTPS-hosted Web pages cannot use it, and it does not provide TLS, Internet reachability, or Desktop/Android interoperability. No recipient-delivery receipt is exposed.

Release gates remain: supported-browser compatibility beyond managed Chromium; WebRTC LAN/NAT/TURN and secure WebSocket relay or HTTPS-compatible native bridge; OPFS crash, rollback, quota and same-profile contention matrix; accessibility and content-isolation review; dependency/CSP and privacy review; and external protocol/security review. WEB-001–009 remain traceable requirements, not all-complete claims.
